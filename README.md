# 인건비 내비게이터

원주시시설관리공단 공모과제 ③ "AI 기반 인건비 산출 및 관리 효율화"에 제안하는, **기업이 등록한 착수계와 업체 산출내역을 AI가 읽어 공단 표준 양식으로 산출·검증하고, 관리자 검수 후 착수계까지 만드는 인건비 산출·관리 플랫폼**의 시연 앱입니다.

- 용역 기업은 착수계 내용을 **채용정보 등록처럼 단계별 양식**에 입력해 등록합니다.
- 관리자는 **금액 산출 계산기**에 업체 파일(엑셀·CSV·Word 표·텍스트 PDF)을 올리면 **AI 문서 인식 모듈**이 핵심 값을 읽고, 계산 엔진이 공단 산정 금액을 만듭니다.
- 누락(주황)·미달(빨강)·과지급(보라)·확인 필요(노랑)를 색으로 표시하고, 항목마다 **오류 정정 필요(☑)** 를 붙입니다.
- **최종 산출물은 관리자가 검수 체크리스트를 마친 뒤에만** 만들어집니다. 관리자 계정 하나만으로도 처음부터 끝까지 작업할 수 있습니다.
- 급여 기준이 바뀌면 관리자가 화면에서 업데이트하고, 기준 버전을 남기고, 영향받는 건을 다시 계산해 재검수를 요청합니다.

**AI 문서 인식은 앱 안에서만 동작하며 파일 내용은 밖으로 나가지 않습니다.** 외부 AI API를 쓰지 않고(표 구조 인식 + 규칙 + 문자열 유사도), 인터넷 없이 동작합니다. 추출기는 파일에서 값과 위치만 꺼내고, 금액은 언제나 계산 엔진(`core/calc.py`)이 만듭니다.

## 1. 설치와 실행

Python 3.15에서 검증했습니다. 발표장 인터넷에 의존하지 않도록 **발표 노트북에서 미리 한 번 설치**해 두세요.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

화면은 공공기관 업무시스템 형식(남색 사이드바·기관 상단바·메뉴 경로·상태 색 배지)이며, 색과 글꼴은 `.streamlit/config.toml`, 공통 스타일은 `core/ui.py`, 로고는 `data/brand/`에 있습니다(인터넷 없이 시스템 글꼴 사용).

이 폴더의 `.venv`를 그대로 쓸 때는 `.\.venv\Scripts\python.exe -m streamlit run app.py` 만 실행하면 됩니다. 브라우저에서 http://localhost:8501 을 엽니다.

### 시연 계정

| 아이디 | 비밀번호 | 표시명 | 역할 | 담당 |
|---|---|---|---|---|
| `company_a` | `demo1234` | 가상기업A(청소) | 기업 | C-001 근로자종합복지관 청소용역 |
| `company_b` | `demo1234` | 가상기업B(청소) | 기업 | C-002 가상 시설 청소용역(시연용) |
| `admin` | `demo1234` | 공단 관리자A | 공단 관리자 | 전체 |

시연용 가상 계정입니다(`data/accounts.yaml`, 솔트 해시로만 저장). 기업 계정에는 **착수계 등록·관리** 화면 하나만 보이고(자기 등록물만), 관리자에게는 10개 화면이 모두 보입니다. 사이드바 **계정 전환**으로 같은 앱에서 바로 바꿀 수 있습니다. 관리자는 계산기에서 **계정 없는 업체를 직접 추가**할 수 있습니다.

발표 직전에 사이드바 **시연 초기화**를 누르세요. 기준(버전 이력 포함), 생년월일, 등록물(가상기업B v1만 남김), 계산기 회차, 정정·검수 기록, 추출 보조값, 로그인, **이력 로그까지** 처음 상태로 돌아갑니다. 보관할 이력은 먼저 CSV로 내려받으세요.

**버튼으로 진행하기:** 사이드바 **🎬 시연 시나리오**에서 고르고 **다음**을 누르면 필요한 계정 전환까지 자동으로 합니다(이력에는 정상적인 로그인으로 남음).

- **시나리오 1 기업 등록 → 관리자 검수:** 가상기업A 로그인 → 새 착수계 등록(일급 90,085원 → 미달 경고) → 95,767원으로 고쳐 등록 → 관리자 로그인 → 등록 목록 → B를 계산기로 보내 AI 추출(누락·미달·과지급 색, ☑) → B 보완 요청, A 검수 → A 착수계 4종 생성·승인 → 이력
- **시나리오 2 관리자 단독:** 관리자만 로그인 → 가상기업C 직접 추가 → PDF 올리기 → 추출 결과(원문 위치·확신도) → 산정기준 확인 → 과지급 1건 정정 → 검수 완료 → 산출내역서 생성
- **시나리오 3 기준 변경:** 2027 기준 적용(기준 v2) → 영향 건 재산출 → "기준 변경으로 재검수 필요" → 재검수 → 재제출 요청 공문

## 3. 데이터 출처, 개인정보, 가상 데이터 범위

**실제 자료** (`data/source/`, 제공 원본의 읽기 전용 사본이며 수정하지 않습니다): 2027년 근로자종합복지관 청소용역 산출내역, 기간제근로자 인건비 산출내역(2026년 9월), 공공부문 도급 노동자 보호지침(2026.9.9 시행).

**개인정보 최소화:** 착수계와 계산기는 인원·직종·근무형태·근무시간·금액만 다룹니다. 실명·주민등록번호·계좌·연락처 입력칸이 없고, 올린 파일에 그런 열이 있으면 읽지 않고 버린 뒤 "개인정보 열 N개는 읽지 않았습니다"라고 알립니다. 투입인력은 `투입인력1`, `투입인력2`…로 표시하고, 업로드 원본은 저장하지 않습니다(파일명·크기·해시와 추출 결과만).

**연도별 기준값**의 단일 원본은 `data/연도별_기준값.json`입니다. 화면에서 기준을 바꾸면 `data/기준이력/v{n}.json`으로 버전이 남습니다.

| 국민연금 | 10%(사용자·근로자 각 5%), 2033년까지 매년 0.5%p 인상해 13% | 확정(법정 단계 인상) |

**시연용 가상 또는 가정 데이터**

- **가상 기업 3곳과 파일**(`data/demo_vendors/`, `scripts/make_demo_vendors.py`):
  - 가상기업A `가상업체A_산출내역.xlsx` — 항목명만 다르고 공단 기준을 모두 충족하는 **승인 가능 자료**(판정 0건). 내용이 바뀌지 않도록 생성 스크립트는 이 파일을 다시 만들지 않고, 테스트가 해시로 확인합니다.
  - 가상기업B `가상업체B_산출내역.xlsx` — 옛 일급 90,085원(미달), 연차수당 누락, 피복비 두 번 계상(과지급), "작업용품"(연결 확인 필요), "성명" 열(버려짐).
  - 가상기업C `가상업체C_산출내역.pdf` — 텍스트 PDF, 계정 없는 업체(관리자 단독 시연), 일반관리비 10%(과지급 1건).
- **C-002 계약**, 계약기간·낙찰률·가상 생년월일(`data/contracts.yaml`), **시연 계정**(`data/accounts.yaml`)
- **착수계 일반 양식**: 모든 문서 머리에 "일반 양식(가정) · 공단 서식 확정 후 교체"와 "검수 완료: 관리자, 시각, 기준 버전"을 표시합니다.
- **판정 기준**(`data/판정기준.json`, 가정): 공단 산정 대비 1% 초과 차이 → 미달·과지급, 일반관리비 9%·이윤 10% 상한, 확신도 0.85 미만 → 확인 필요.
- **아르바이트 4대보험 예외**, **프리랜서 산재 노무제공자 특례**는 "확인 필요"로 표시합니다.
- **국민연금 2028년 이후 영향표**는 다른 기준을 현행 유지로 가정합니다.
- 근태 기록·임금명세서 제출액(가상), 총인건비(참고 기능)의 기준액·인상률·실적(`data/총인건비_기준.json`)

**발표 전 확인할 점**

- 착수계 서류는 일반 양식입니다. 공단 서식이 정해지면 `core/startup_docs.py`의 양식만 바꾸면 됩니다.
- 판정 기준(1%, 상한)은 가정값입니다. 공단 기준으로 `data/판정기준.json`을 교체하세요.
- 공단 산정의 장기요양은 법정 요율(2026년 13.14%)을 씁니다. 원본 산출내역의 12.95%는 옛 요율로 표시됩니다.
- 원본의 실수령액 수식은 9명 모두 정상입니다. "수식 누락" 실제 사례는 D31이고, 실수령액 사례는 주입본입니다.
- 국민연금 누락 4건·제외 2건은 **가상 생년월일 기준**입니다. 계약기간 위반(4-1)은 1년 가정값 기준입니다.
